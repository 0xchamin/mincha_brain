## Dropped / divergences (audit trail)

| Candidate | Verdict | Note |
|---|---|---|
| `fig2` vs "a big architectural shift" | **divergence** `d1` | **The figure captioned "LangChain's data stack architecture" shows a stock modern ELT pipeline with no agent in it.** Sources (billing, 3rd party, internal services, event tracking) -> Metronome / Fivetran / Airbyte / Postgres / Segment -> Loading -> Raw data -> Transforming (dbt) -> Prod -> Reporting, inside a BigQuery boundary, with Hex attached at the right edge and GitHub feeding dbt. **No semantic model, no workspace guides, no endorsements, no agent and no feedback loop appear anywhere in it** - every one of those lives only in `fig3`. The prose calls the migration "a big architectural shift". Both are defensible, and the tension is the finding: **the shift was to the reporting tier and the documentation around the warehouse, not to the data architecture.** The ingestion and transformation plumbing is what it would have been in 2022. This is the single most useful thing the visual leg contributed. |
| `fig3` has no human in it | **divergence** `d2` | The prose's feedback loop has six steps and **two of them are human**: "Data team reviews patterns and suggestions" and "Data team updates models, definitions, guides, metrics, endorsements, or dashboards". The endorsement guardrail is stronger still - "only the data team can mark something as endorsed", and endorsed dashboards "require data team review before changes go live". In `fig3` the dashed feedback arrow runs from "Usage trends" **straight back into the dbt box with no review step**, and the diagram contains no human actor anywhere. Secondary: the prose's step 1 (users asking via Hex, Slack, CLI, MCP, LangSmith Fleet) has no counterpart in the figure either. **The one control that makes the design trustworthy is prose-only.** Recorded, not resolved - the likely explanation is diagram simplification, but a reader who took `fig3` as the specification would build an unguarded self-modifying context loop. |
| The 40x denominator | **divergence** `d3` | **Unit mismatch plus an unmeasured baseline.** The numerator is **2,200 agent conversations**; the denominator is the request volume a 3-person team "could field **directly**" - a capacity estimate, never a measurement. Back-solving gives ~55 requests/month across three people, ~18 per person per month. Two problems: **a conversation is not a request** (a user asking four follow-ups produces four conversations or one long one depending on the tool, and neither equals one answered question), and the counterfactual capacity is asserted. The article is not overclaiming - "could field directly" is offered as an illustration - but the number should never be quoted bare. |
| Volume measured, quality not | **divergence** `d4` | Not an internal contradiction, an **omission**, and the most important one in the source. Every reported figure is adoption: conversations, users, coverage, migration speed. The article's own thesis is that context makes answers **trustworthy** ("the answers are harder to trust", "the reliability of a data agent comes from the context") - and **trustworthiness is the one property never measured**. `n10` shows the authors know. The consequence: the 40x is a throughput claim standing where a correctness claim is needed, and 40x the volume at an unknown accuracy is not obviously better than 1x at a known one. See `context/01_data-agent-accuracy-and-prior-art.md` for what the field has measured here. |
| MCP as an access surface | **dropped as a source for `brain/topics/mcp.md`** | MCP appears exactly twice, both times as a bullet in a list of ways to reach the agent ("The Hex UI... Slack, CLI workflows, MCP, LangSmith Fleet, through MCP and CLI integrations"). **No mechanism, no primitive, no version, no design consequence.** This is precisely the case [ADR-0012](../../brain/decisions/0012-a-mention-is-not-a-source.md) was written for - **a mention is not a source** - so the MCP topic stays at one source and does **not** advance. Worth one sentence in `LEARNING.md` as evidence that MCP has become an unremarked-upon delivery default, which is itself mildly interesting. |
| The Hex selection narrative | dropped | "We ended up choosing Hex", the vendor evaluation criteria, and the single-workspace argument are real operational content but **not transferable** - a procurement decision for one company. Retained only as the testimonial caveat in `SOURCE.md`. Signal, not archive. |
| The data team growing 1 -> 3 people | dropped as a node, kept as context | Stated in passing ("At the time, that team was just one person") and never reconciled with the 3-person figure used in the headline. Relevant only as background to `d3`. |
| Six-week migration, self-serve IT provisioning | dropped | Operational trivia specific to one company's rollout. |
