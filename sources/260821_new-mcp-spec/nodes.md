| n7 | **CIMD replaces DCR by making the `client_id` a hosted HTTPS URL that the authorization server fetches on demand, so no registration record is ever written.** The client hosts a metadata JSON document at a stable URL; that URL *is* the `client_id`; the AS detects the URL form and GETs it instead of writing a record. | n8 | **Before MRTR, an elicitation pinned a server instance for as long as the human took to answer.** The server held the in-flight tool call *and* an open SSE stream; when the answer finally came back, the load balancer had to deliver it to that exact instance. | n9 | **MRTR replaces that with two independent requests joined by an opaque blob the client carries.** The server answers "I need more" with an `input_required` result plus a `requestState` blob and ends the request holding nothing; the client prompts the user whenever it likes; the client re-sends the original call with `inputResponses` plus the echoed `requestState`, and **any instance** reconstitutes the state and finishes. Kent: "in six days the user could provide a response, it doesn't matter, we're not taking up any resources for that." | `visuals/frame_1310.jpg` - Kent's AFTER diagram: "Original request ends. Nothing is held in server memory", "Server reconstitutes state from requestState + inputResponses", and the closing green band "Any instance can handle the retry. ## What this source is good for, and what it is not

**Good for:** the shape of the `2026-07-28` release from someone who shipped against it; the DCR ->
CIMD mechanics, which no prior source in this brain explains; MRTR drawn as a before/after pair; and
**the only adoption measurement in the brain**, with the instrumentation that produced it shown in
the diff.

**Not good for:** anything about the specification's *rationale*, which Kent reads off the blog post
rather than sourcing; adoption beyond one hobbyist-scale server with a self-selected client
population; and security analysis, where `n10` states an obligation that neither this source nor S23
tests any implementation against.
