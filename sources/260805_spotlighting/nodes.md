# Knowledge nodes - Spotlighting (Hines et al., Microsoft)

> Persona: **fact-checker** - re-adopt when working this file.

> Each node has a **stable ID** (`n1`, `n2`, ... - never renumber), a claim, **both legs each with
> its own citation** (or one leg marked `single-leg`), a gate verdict, and a confidence.

> **The scope note that governs every number below.** All evaluation is on **document summarization
> and Q&A** - single-turn, no tool calls, no environment state (`d3`). The threat model S17 describes,
> and the one this brain cares about, is an **agent with tools**. Nothing here is tested against it.

## Nodes

| ID | Claim (crux) | Evidence leg + citation | Corroborating leg + citation | Gate | Confidence |
|---|---|---|---|---|---|
| n1 | **The root cause, stated in security terms: the LLM cannot distinguish code from data**, because it operates on boundary-less streams of tokens | §1, "In security parlance, the LLM is not able to distinguish code from data. In this case, code refers to system instructions that the designers implement and data refers to any text that we do not control ... This is a structural limitation of LLMs since they operate on boundary-less streams of tokens", p1 | §3.1, "The prompt injection problem stems from the LLM's inability to distinguish between valid system instructions and invalid instructions that arrive from external inputs", p2 | corroborated | OK. **Independently restates S17's `n1`** - Microsoft, 2024, no author overlap with Saarland/CISPA |
| n2 | **Spotlighting is a family of *input transformations* that make provenance continuously salient**, paired with a system prompt explaining the transformation. Three instantiations: delimiting, datamarking, encoding | §3.1, "there are two primary components. First, the input text is subject to (optional) transformations before it reaches the prompt template. Second, the system prompt is updated to include detailed instructions about the input text and how it should be treated", p2 | §3.2-3.4, each instantiation given with a worked system prompt, p2-3 | corroborated | OK |
| n3 | **Telling the model to ignore injected instructions barely works on its own** - adding defensive instructions to the system prompt has "almost no added benefit" for GPT-3.5-Turbo and a noticeable but insufficient effect on Text-003 | `visuals/fig3_delimiters.png` - Baseline ~0.60 and "+ Instructions" ~0.58, essentially unchanged | §4.2, "the addition of instructions about prompt injection has almost no added benefit. For Text-003, the impact is noticeably better, but with a significantly high ASR remaining", p3 | corroborated | OK. **The baseline everyone tries first, measured failing** |
| n4 | **Delimiting halves attack success and the authors recommend against using it**, because an adversary who learns the system prompt can craft input containing the delimiters and override the instructions | `visuals/fig3_delimiters.png` - "+ Instr + Delimiters" drops ASR from ~0.60 to ~0.30 | §5.4, "Starting with delimiting, it is easy to see that this approach can be bypassed. If an adversary gains knowledge of our system prompt ... For this reason, we do not recommend using delimiting in practice, but include it here for comparisons", p6 | corroborated | OK. **Note this is the variant S20 later evaluated** (`d3`) |
| n5 | **Datamarking is the large win: interleaving a special token throughout the input drops ASR from ~50% to 3.10% on GPT-3.5-Turbo and from ~40% to 0.00% on Text-003** in summarization, with a Q&A task giving 8.0% / 1.0% / 0.00% across Turbo, GPT-4 and Text-003 | `visuals/fig4_datamarking.png` - Baseline bars near 0.5 and 0.42, Mark bars at ~0.03 and ~0.00 | §5.1, "With GPT3.5-Turbo, ASR is reduced from approximately 50% to below 3%. With Text-003, ASR is reduced from 40% to 0.00%", p4 | corroborated | needs-check on transfer (`d3`). **`d3` is now closed externally, 2026-08-05**: AgentDyn evaluates Spotlighting on a tool-calling agent and reports **52.24% utility under attack at 27.61% attack success** on GPT-4o, concluding prompting-based defences "only slightly reduce ASR". **The low utility cost holds; the security benefit does not transfer** - see [S18 context/01](../260804_camel-prompt-injection-defense/context/01_independent-evaluation-and-the-2026-defence-landscape.md) |
| n6 | **Datamarking costs nothing measurable on the underlying task** - across SQuAD Q&A, IMDB Sentiment, SuperGLUE WiC and SuperGLUE BoolQ, accuracy with datamarking tracks the baseline | `visuals/fig7_datamarking_no_task_cost.png` - four benchmark pairs, Baseline and Mark bars within noise of each other | §5.2, "the presence of the datamarking transformation does not have any detrimental impact on task performance", p5 | corroborated | OK. **The finding that makes it deployable** |
| n7 | **Encoding gives the lowest attack success and is the only technique with a real capability requirement** - ASR 0.0% on summarization and 1.8% on Q&A, but task accuracy collapses on GPT-3.5-Turbo while GPT-4 is barely affected | `visuals/fig8_encoding_task_cost.png` - GPT-4 accuracy is near-identical with and without encoding, while GPT-3.5-Turbo falls from ~0.85 to ~0.58 on SQuAD and from ~0.92 to ~0.50 on Sentiment | §5.2, "GPT-3.5-Turbo suffers in task performance when faced with encoded text ... In contrast, GPT-4 is able to consistently perform quite well even with encoded text. Therefore, we recommend that encoding only be used with the highest-capacity models", p5 | corroborated | OK |
| n8 | **The recommendation is datamarking by default**, encoding only on high-capacity models with per-use-case validation, and delimiting not at all | §5.3, "we recommend that we default to datamarking ... as it has a large improvement over delimiting ... if high-capacity LLMs are being used (such as GPT-4), our ultimate recommendation is to use an encoding approach", p5 | §5.4's adversary analysis, which is what disqualifies delimiting, p6 | corroborated | OK |
| n9 | **The adversary model is "assume the system prompt has leaked", and it forces the marking token to be dynamic.** Static whitespace-based datamarking is defeated by an attack string containing no spaces, so the authors recommend randomised marking tokens and randomised interleaving positions, giving an adversary a `1/N^k` chance of guessing | §5.4, "we must assume that our entire system prompt has been leaked to an adversary ... By frequently changing the marking tokens, we reduce the risk of such a leak ... an adversary would have an 1/N^k chance of guessing it correctly", p6 | §5.4, "it is easy to imagine an attack string which contains no spaces. This attack would then not be interleaved with the marking token at all", p6 | corroborated | OK. **The best piece of defensive engineering in the paper** |
| n10 | **A reversible encoding is exploitable: with ROT13 the attacker simply writes text whose ROT13 image is the desired attack**, so the transformation must be one the attacker cannot invert | §5.4, "if that attacker had knowledge of this system ... the attacker would only need to arrange their attack text such that its ROT13 representation is actually the desired plaintext attack ... our system would then (inadvertently) transform it into the plaintext attack", p6 | §5.4, "we need to choose a mechanism that cannot be subverted by an attacker even if they had perfect knowledge of the transformations ... This yields a one-way transformation that the attacker cannot control", p6 | corroborated | OK |
| n11 | **The authors do not know why spotlighting works** | §6, "While the data presented here seem to indicate that this intuition is correct, we lack a clear understanding of *why* spotlighting actually helps", p6 | (none - an admission has no second leg) | single-leg | OK. **Recorded because it is exactly the property S18 objects to in heuristic defences** |
| n12 | **The telecom analogy, and it is the paper's most valuable idea: spotlighting is in-band signalling, and the real answer is out-of-band.** Early telephony shared one channel between control and voice data; multi-frequency in-band signalling separated them enough to stop *accidental* interference but was defeated *intentionally* by phone phreaking; the fix was out-of-band signalling on a separate channel (SS6, SS7). **LLMs are worse than early telecom**, because all tokens are treated roughly equally with no ability to distinguish blocks | §6, "it would be as if the control data ... were transmitted in a frequency space that overlapped with typical frequencies of human voices", p6 | §6, "Spotlighting helps to create separation but is **not perfectly secure against intentional interference** ... it would seem that we need to devise a multi-channel analog for LLMs ... With current architectures of common language models, however, this is not feasible in any straightforward way", p7 | corroborated | OK. **The authors conceding the ceiling of their own method, and naming the shape of the answer a year before S18 built one** |
| n13 | **Few-shot examples cut ASR below 5% and the authors argue against relying on them** - in-context learning is bounded by the defender's current knowledge of attack tactics, and there is a label-leakage risk because the examples correlate with the test set | §8.2, "the ASR is reduced to below 5% ... However, these results, and the strategy of using few-shot examples, must be taken with caution for two primary reasons", p8 | §8.2, "we are bedeviled by a contemporary version of the classic overfitting problem, but now framed as few-shot learning ... We prefer instead to rely on spotlighting techniques which target the structural problems", p8 | corroborated | OK. **A vendor declining to quote its own best number, which is worth noting** |
| n14 | The headline claim: **attack success falls from over 50% to below 2% with minimal impact on task efficacy** | Abstract, "we find that spotlighting reduces the attack success rate from greater than 50% to below 2% in our experiments with minimal impact on task efficacy", p1 | §5.1 and §5.2 results, p4-5 | corroborated | needs-check - **the headline is a best-case composite** (`d2`) |

## Dropped / divergences (audit trail)

| Candidate | Verdict | Note |
|---|---|---|
| `d1` - **vendor defending its own attack surface** | **divergence** | All six authors are **Microsoft**, and the related work cites the compromise of **Bing Chat** as motivating evidence. So this is the vendor of a compromised product publishing the mitigation for it, with **no code release and no venue**. Not a reason to discount the mechanism, and it places the source in S12's evidential class rather than S20's. Note also that S17's `n12` - the finding that Bing Chat filtered its chat channel and not its retrieval channel - is a finding *about these authors' employer*, published thirteen months earlier |
| `d2` - the headline is a best-case composite | **divergence** | ">50% to below 2%" takes the **best technique** (encoding) on the **best model** for the **best task**. The paper's own tables show datamarking on GPT-3.5-Turbo Q&A at **8.0%**, and delimiting - the variant most teams actually implement - at roughly **30%**. **Finding, kept**: the abstract number is achievable and is not what a typical deployment gets |
| `d3` - **nothing here is agentic, and the one variant later tested in an agentic setting is the one the authors disown** | **divergence, and the most consequential for this brain** | Every experiment is document summarization or Q&A: single-turn, no tool calls, no environment state. **S20 (AgentDojo) evaluates "data delimiters, where following Hines et al. we format all tool outputs with special delimiters"** - which is `n4`, the variant this paper explicitly recommends against - and finds only a modest ASR reduction in an agentic setting. **So datamarking and encoding, the two techniques actually recommended here, have never been evaluated against a tool-calling agent by anyone in this brain's evidence.** That gap is this brain's finding, not either paper's |
| `d4` - a defence whose mechanism its authors cannot explain | noted, and it interacts with S18 | `n11` states plainly that they lack a clear understanding of why spotlighting helps. S18's objection to the whole heuristic family is that "none of these heuristic defenses provide any guarantee of security", and an unexplained mechanism is precisely what makes a guarantee impossible. **The two papers agree**; see `n12`, where these authors reach the same conclusion by their own route |
| Figure 1, Figure 2, Figure 5, Figure 6, Figure 9, the ASR/AffSR appendix | dropped | Baseline ASR by model, the instructions-only result (carried by `visuals/fig3_delimiters.png`), datamarking on Q&A and encoding's ASR (both quoted numerically in `n5` and `n7`), the few-shot result (`n13`), and the measurement-protocol appendix |
| Code or dataset | **none exists** | The paper describes a synthetic corpus of 1000 attack documents and releases neither it nor any code. **This is the only source in the security set with nothing to inspect**, which matters for a defence whose effect its authors cannot explain |
