Kept as `d1`: a docs-vs-code divergence of exactly the class the contract says to record, and a useful reminder that a vendor code sample is evidence of intent, not of a working API. |
| The Recall@10 comparison | **divergence** | `d2` - **the head-to-head is not one experiment.** The caption states plainly that "BM25s, BGE-reranker-v2-gemma results are **from [1]**", i.e. lifted from another paper, while the tool-search column is Microsoft's own run. The article also says that run "used only the user query and left out the benchmark's instruction string", justified on cost and latency grounds. **Whether [1] also omitted it is never stated**, so the columns may not be like-for-like. The direction of the bias is unknown, which is the problem: if [1] used the instruction string the comparison flatters the borrowed baselines, and if it did not, it flatters tool search. |
| Auto-pinning vs prompt-cache stability | **divergence** | `d3` - **an internal tension inside one paragraph.** A pin set that is chosen automatically, computed **per user**, warmed up over time and aged out as usage shifts is by construction neither identical across users nor stable across days. The very next sentence claims "Deterministic pinning keeps the prompt prefix stable, which preserves prompt-cache behavior". Both can be true only if "deterministic" refers to *manual* pins alone, which the text does not say. Recorded rather than resolved. |
| Figure 2's baseline discontinuity | **caveat on `n9`, not a separate node** | The baseline series jumps from roughly 160k to roughly 360k tokens between about 500 and 550 tools - **more than a 2x step for a ~10% increase in catalog size** - then resumes a gentle climb. A clean single-variable ablation over one benchmark should not produce that. The prose describes the run as an ablation that "increased the number of tools available to the model" and never mentions the discontinuity. It does not threaten the headline (541k vs 15k), which is measured at the right-hand end, but it does mean the curve is not the smooth sweep the prose implies. |
| The retrieval level itself | **kept as the source's central unexamined gap** | Not a divergence, an omission, and the most important one. **Recall@10 of 39-46% means the needed tool is outside the top ten more than half the time**, while `limit` defaults to **five**. The implicit answer is `n15` (tuning recovers to within ~4% of the full-catalog baseline end-to-end) - but that is a different metric on a different, unnamed eval, so the gap stands. Combining `n11`, `n15` and the closing paragraph is **this brain's reading of the source's own numbers**, not a claim the source makes. |
